## Module Descriptions

### 1. PR Creation Module (`pr_creation.py`)

**Purpose:** Automatically create GitHub pull requests with comprehensive descriptions

**Key Features:**

- Database-backed PR tracking
- Auto-generated PR descriptions
- Issue linking and cross-referencing
- Batch PR creation for multiple tasks
- GitHub API v3 integration

**Main Class: `PRCreator`**

```python
class PRCreator:
    def __init__(self, db_session: Session)
    def create_pr(task_id: int, repo: str) -> dict
    def create_pr_from_issue(issue_number: int, repo: str) -> dict
    def get_pr_status(task_id: int, repo: str) -> dict
    def list_prs_for_repo(repo: str) -> list
    def auto_create_prs_for_completed(repo: str) -> dict
```

**Sample PR Description:**

```markdown
# Resolve Issue #42

## Analysis & Plan
- Analyzed issue requirements
- Generated implementation plan
- Created proof of concept

## Changes Made
- `src/auth.py` - Added 150 lines
- `src/security.py` - Added 200 lines
- `tests/test_auth.py` - Added 100 lines

## Testing
- Unit tests: ✅ 15/15 passed
- Security scan: ✅ No issues
- Code review: ✅ Auto-approved (score: 8.5/10)

---
*Auto-generated by KOR'TANA Autonomous System*
```

### 2. Code Review Module (`code_reviewer.py`)

**Purpose:** Perform AI-powered code review with security scanning and approval logic

**Key Features:**

- Pattern-based security vulnerability detection
- Code quality metrics analysis
- Gemini AI-powered review generation
- Auto-approval decision logic
- GitHub PR commenting integration

**Security Patterns Detected:**

| Pattern | Detection Method | Risk Level |
|---------|-----------------|-----------|
| SQL Injection | Regex patterns for dynamic SQL | 🔴 Critical |
| Hardcoded Credentials | Detect API keys, tokens, passwords | 🔴 Critical |
| Unsafe eval() | Detect eval, exec, **import** | 🟠 High |
| Insecure Deserialization | Detect pickle, yaml, json.loads | 🟠 High |

**Code Quality Metrics:**

```python
{
    "line_count": 120,           # Total lines
    "empty_lines": 20,           # Blank lines
    "comment_ratio": 0.25,       # Comments / code
    "avg_line_length": 45,       # Average line length
    "long_lines": 5,             # Lines > 100 chars
    "issues": [
        "Line 45 too long (125 chars)",
        "Low comment ratio"
    ]
}
```

**Main Class: `CodeReviewer`**

```python
class CodeReviewer:
    def scan_for_security_issues(code: str) -> list
    def check_code_quality(code: str) -> dict
    def generate_review(code: str, plan: str) -> dict
    def should_auto_approve(review: dict) -> bool
    def create_review_comment(review: dict) -> str
    def post_review(owner: str, repo: str, pr_number: int, review: dict,
                   token: str, dry_run: bool = False) -> dict
```

**Auto-Approval Criteria:**

```python
# Auto-approve if:
auto_approve = (
    score >= 8.0 and  # Code quality score
    recommendation == "approve" and  # AI recommendation
    no_security_issues  # No critical security issues
)
```

**Review Score Breakdown:**

- 9-10: Excellent (auto-approve)
- 7-8: Good (review recommended)
- 5-6: Acceptable (improvements needed)
- 0-4: Poor (reject & request changes)

### 3. Test Orchestration Module (`test_orchestrator.py`)

**Purpose:** Orchestrate automated test execution with coverage validation

**Key Features:**

- pytest integration with coverage reporting
- Test discovery and selective execution
- Code quality checks (linting, type checking)
- Full CI/CD pipeline automation
- Coverage threshold enforcement

**Main Class: `TestOrchestrator`**

```python
class TestOrchestrator:
    def discover_tests(test_dir: str = "tests") -> list
    def run_tests(test_path: str = "tests", verbose: bool = True,
                 coverage: bool = True, markers: str = None) -> dict
    def parse_coverage(coverage_json: str = "coverage.json") -> dict
    def check_coverage_threshold(threshold: float = 80.0) -> bool
    def run_specific_tests(test_names: list) -> dict
    def run_linting() -> dict
    def run_type_checking() -> dict
    def run_full_pipeline() -> dict
```

**Full Pipeline Sequence:**

```
1. Linting (flake8)
   └─ Check code style, unused imports

2. Type Checking (mypy)
   └─ Validate type hints and contracts

3. Unit Tests (pytest)
   └─ Run all tests with coverage

4. Coverage Validation
   └─ Enforce minimum threshold (80%)

5. Report Generation
   └─ Collect metrics and statistics
```

**Coverage Report Format:**

```json
{
    "percent_covered": 87.5,
    "num_statements": 400,
    "num_missing": 50,
    "files": 15,
    "status": "PASS"
}
```

## Integration Workflows

### Workflow 1: Complete Autonomous Issue Resolution

```
1. Issue Created on GitHub
   └─ "Add user authentication"

2. Autonomy Router Processes
   └─ Analyzes issue using Gemini
   └─ Generates implementation plan
   └─ Creates GitHubTask record

3. Code Generation
   └─ Generates code from plan
   └─ Creates necessary files
   └─ Validates syntax

4. [NEW] PR Creation
   └─ Creates pull request with auto-generated description
   └─ Links to original issue (#42)
   └─ Updates GitHubTask.github_pr_number

5. [NEW] Code Review
   └─ Scans for security vulnerabilities
   └─ Analyzes code quality
   └─ Generates AI review using Gemini
   └─ Auto-approves if score >= 8.0

6. [NEW] Test Orchestration
   └─ Runs full test pipeline
   └─ Validates coverage threshold
   └─ Generates test reports

7. Auto-Merge (if approved)
   └─ Merges PR if all checks pass
   └─ Closes related issue
   └─ Updates GitHubTask.status to "merged"
```

### Workflow 2: Security-First Code Review

```
1. Code Submitted for Review
   └─ POST /review/scan-security

2. Security Scanning Phase
   ├─ SQL Injection detection
   ├─ Credential hardcoding check
   ├─ Unsafe eval() detection
   └─ Insecure deserialization check

3. Code Quality Analysis
   ├─ Line length validation
   ├─ Comment ratio calculation
   ├─ Code complexity metrics
   └─ Style consistency

4. AI Review Generation
   ├─ Sends to Gemini API
   ├─ Gets structured review
   └─ Calculates confidence score

5. Decision Logic
   ├─ Score >= 8.0?
   ├─ Recommendation == "approve"?
   └─ No critical security issues?

6. Auto-Approval
   └─ If all criteria met:
      └─ Auto-approve PR
      └─ Post comment with review
      └─ Mark for merge
```

### Workflow 3: Test Validation Pipeline

```
1. Test Discovery
   └─ Find all test_*.py files

   └─ Build test catalog

2. Linting Phase
   ├─ Run flake8
   ├─ Check style compliance
   └─ Validate imports

3. Type Checking Phase
   ├─ Run mypy
   ├─ Validate type hints
   └─ Check contracts

4. Unit Testing Phase
   ├─ Run pytest suite
   ├─ Collect coverage data
   └─ Generate reports

5. Coverage Validation
   ├─ Parse coverage.json
   ├─ Compare to threshold (default: 80%)
```

## Security Implementation

### Threat Model

| Threat | Mitigation | Verification |
|--------|-----------|--------------|
| Token exposure | Environment variables only | ✅ No hardcoded tokens |
| SQL injection in code | Pattern detection + AI review | ✅ Tested with OWASP patterns |
| Credential leakage | Regex scanning for API keys | ✅ Detects sk_, AKIA, pk_ patterns |
| Unsafe deserialization | Pickle/yaml detection | ✅ Pattern matching |
| Rate limiting bypass | GitHub API rate checking | ✅ Headers validated |
| Unauthorized access | Token validation on all endpoints | ✅ Guard clauses added |

### API Security Headers

All endpoints should enforce:

```python
# Required headers
SECURITY_HEADERS = {
    "X-GitHub-Token": "encrypted_token",
    "Authorization": "Bearer token",
    "X-Request-ID": "unique_id",
}

# Rate limiting
RATE_LIMIT = {
    "requests_per_minute": 60,
    "burst_size": 10,
    "window": 60,
}
```

### Token Management

```python
# Environment-based (recommended)
GITHUB_TOKEN = os.getenv("GITHUB_TOKEN")
GEMINI_API_KEY = os.getenv("GEMINI_API_KEY")

# Never use:
# - Hardcoded tokens
# - Tokens in config files
# - Tokens in logs
# - Tokens in error messages

# Validate on startup:
if not GITHUB_TOKEN:
    raise TokenConfigurationError("GITHUB_TOKEN not configured")
```

## Troubleshooting

### Common Issues

**Issue: "GitHub token not configured"**

```bash
# Solution:
export GITHUB_TOKEN="your_token_here"

# Verify:
python -c "import os; print(os.getenv('GITHUB_TOKEN'))"
```

**Issue: "PR creation fails with 401"**

```bash
# Solution: Token expired or invalid
# 1. Check token permissions (repo, workflow scopes)
# 2. Regenerate if expired
# 3. Verify in GitHub settings
```

**Issue: "Code review score too high/low"**

```bash
# Solution: Adjust Gemini prompt or scoring logic
# File: backend/routers/code_reviewer.py
# Method: generate_review()
# Adjust: score calculation or Gemini system prompt
```

**Issue: "Test coverage below threshold"**

```bash
# Solution: Add more test cases
# 1. Identify untested code
# 2. Create test_*.py for uncovered modules
# 3. Use fixtures for setup/teardown
# 4. Mock external dependencies
```
